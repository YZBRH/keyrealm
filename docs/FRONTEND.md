## Element Plus 按需引入

组件与图标**不做全量注册**：`main.js` 不 `app.use(ElementPlus)`，改为在 `vite.config.js` 里挂
`unplugin-vue-components` 的 `ElementPlusResolver({ importStyle: 'css' })`，模板里写到哪个组件就
只打包哪个（图标同理，`<el-icon><Search /></el-icon>` 里的 `Search` 由 resolver 自动引入）。

三条必须知道的约束：

- `dirs: []`、`dts: false`——只解析 Element Plus 自身的名字，不扫本地组件目录（本地组件一律显式
  `import`），也不生成 `components.d.ts`。
- **命令式组件要手工引样式**：`ElMessage` / `ElMessageBox` / `ElNotification` / `ElLoading` 这类
  以函数调用的服务不走模板解析，resolver 看不到它们。样式统一在 `main.js` 显式 `import`；
  `v-loading` 指令的样式也走指令解析路径，缺了它 loading 遮罩会变成纯文字。
- `import '@/styles/index.css'` **必须放在所有 Element Plus 样式之后**，否则主题令牌会被
  EP 的默认色阶盖回去。

> 按需引入的收益（同一份源码的两种构建对照）：CSS **425.77 → 231.43 kB（−45.6%）**、
> JS **1339.80 → 742.56 kB（−44.6%）**。

## 主题与样式层

表现层全部收敛成一套 `--v-*` 令牌，**只作用于表现层，不碰后端**：

- `src/styles/themes/<id>.css` —— 每个主题只做一件事：在 `:root[data-theme='<id>']` 下声明
  **同一份** `--v-*` 令牌（颜色、圆角、阴影、字体、动效时长、背景光斑）。
- `src/styles/base.css` —— 不认识任何具体主题，只消费令牌，并把它**单向**桥接到 Element Plus
  的 `--el-*` 变量。
- 组件不直接写颜色，只消费令牌或 Element Plus 变量。

> 这一层是整体新增的：重构前直接用 Element Plus 默认外观、各组件散写 `scoped` 样式。
> 回退方式见「回退整个表现层」。

### 令牌契约

每个主题文件（`src/styles/themes/<id>.css`）只做一件事：在 `:root[data-theme='<id>']` 下声明
**同一份** `--v-*` 令牌。`base.css` 不认识任何具体主题，只消费令牌——所以加/删主题不会波及组件。

Element Plus 的 9 级色阶（`--el-color-primary-light-3/5/7/8/9`、`-dark-2` 等）由 `--v-primary`
经 `color-mix()` 现算，因此一个主题只需 ~70 行，不必手写几十个色值。调色基色随明暗切换：
`html.dark` 下取页面底色 `--v-bg`（越浅的色阶越往暗处调），浅色下取白色。

毛玻璃的模糊整串（`blur()` + `saturate()`）走**单个**令牌 `--v-glass-backdrop`，而不是拆成
`--v-glass-blur` + `--v-glass-saturate` 两条：这样主题才能把它整体置为 `none`。这不只是写法问题——
Chromium 只要 `backdrop-filter` 的计算值不是 `none`，就会给元素建 backdrop root 并单独提升合成层，
而侧栏、顶栏、每张 `.el-card` 都是常驻元素。默认主题（黑曜）本来就不模糊，改成 `none` 后渲染结果
与 `blur(0px) saturate(1)` 完全一致（两者都是恒等变换），但这些常驻层不再创建。基座里的回退值
写作 `none`：主题若漏配该令牌，结果是「没有毛玻璃」，而不是半截的无效声明。

| 主题 | id | 明暗 | 定位 |
|------|-----|------|------|
| 极光 | `aurora` | 浅 | 渐变 + 毛玻璃 |
| 纸感 | `paper` | 浅 | 暖白纸、编辑/Notion 风 |
| 薄荷 | `mint` | 浅 | 青绿、圆润 SaaS |
| 午夜 | `midnight` | 深 | 深蓝磨砂玻璃 |
| 黑曜石 | `obsidian` | 深 | 近黑、锐利直边、柠檬绿，**默认主题** |
| 星云 | `nebula` | 深 | 紫粉辉光 |

> **默认主题是黑曜石（`obsidian`）**——没有任何已保存偏好时用它。为此
> `themes/obsidian.css` 的选择器写成裸 `:root, :root[data-theme='obsidian']`：裸 `:root`
> 只是首帧写上 `data-theme` 之前那一瞬的兜底，其余主题靠 `:root[data-theme='<id>']`
> 的更高优先级盖过它。**换默认主题**要把裸 `:root` 挪到新默认那份文件里，并同步三处初值：
> `themes.js` 的 `DEFAULT_THEME`、`index.html` 内联脚本的 `id`、`ThemePicker.vue` 的读值兜底。
> `base.css` 的 `:root` 只放与配色无关的共用令牌（光晕公式、动效曲线、色阶混色基底），
> 不再重复任何配色——所以改默认主题不必动它。

背景由 `App.vue` 里一个固定的 `.v-aurora` 层提供（三个**静止**的模糊光斑，取自
`--v-mesh-1/2/3`），内容层靠 `#app` 的 `z-index` 压在其上。因此**主内容区
（`.layout-main`）与侧栏、顶栏都必须保持背景透明/半透明**，否则极光会被挡住。

### 动效原则

**只保留用户操作触发的动画。** 进场动画（`v-fade-in` / `v-fade-up` / `v-pop-in` / `v-msg-in` /
`v-grow-in`）、弹层、悬停、主题切换这类由交互或状态变化驱动的一次性动画保留；**常驻元素不做
无限动画**——logo「呼吸」、侧栏「MCP 运行中」脉冲、解锁/初始化页徽标外圈的扩散环、背景光斑漂移，
这些已经全部改为静态。

理由不止观感：常驻元素的无限 `transform` / `box-shadow` / `opacity` 动画会让所在层持续重新合成，
即便看不出变化，GPU 和 CPU 也一直有开销。判定标准很简单——**信息量为零的常驻闪动不要加**。
连带的另一条：静态元素不写 `will-change`（不动的元素没必要常驻提升合成层）。

**浮层（popper）的进场动画只允许动 `opacity`。** Element Plus 的 popper 默认开
`gpuAcceleration`，定位结果写在内联 `transform: translate3d(x, y, 0)` 上；而 **CSS 动画声明的
优先级高于内联样式**，动画里只要出现 `transform`，动画期间就会顶掉真实坐标——现象是提示框先在
窗口左上角画一帧、再「闪」回正确位置。`translate` / `scale` 独立属性同样不能用（会污染 popper
自身的 rect 测量）。所以 `.el-popper` 统一用只做透明度的 `v-pop-fade`（`base.css`），
以后新增带 `transform` 动画的浮层规则会被这条约定挡下。全仓只有这一条全局 popper 动画，
其余 `transform` 动画都在非浮层元素上，不受影响。

### 明暗切换

Element Plus 的暗色模式靠 `<html class="dark">` 触发（其 `theme-chalk/dark/css-vars.css`
监听该类）。`src/theme/applyTheme.js` 负责把主题 id 写到 `data-theme`，再按主题的 `mode`
增删 `.dark` 类。

`index.html` 里另有一份**等价的内联脚本**，在样式表加载前就执行，避免深色主题首帧白闪
——内联脚本无法 `import` 模块，所以深色主题清单（目前是 `midnight`/`obsidian`/`nebula`）
在 `index.html` 与 `src/theme/themes.js` 各写了一份，**增删深色主题时必须两处同步**；
不一致的唯一后果是深色主题下首帧白闪一下。

主题选择存 `localStorage['vault.ui.theme']`，与 `vault.layout.*` 一样属**纯前端**偏好，不进数据库。

### 运行时切主题

**「系统设置 → 外观」**（`components/ThemePicker.vue`）把 6 套方案平铺成一个卡片网格，按明暗分
两组，每张卡片是一条三色预览条 + 方案名 + 一句话定位；选中的那张带主色描边、辉光与右上角对勾。
点一下即调 `applyTheme()`：写 `<html data-theme>`、按 `mode` 增删 `.dark`、落 localStorage ——
全程不请求后端，换主题不影响任何数据与后台任务。

### 两个疑似回归的判定

判定手法：把带 `--v-primary` 的 `<style>` 标签 `disabled`，同一页面截两张图对照，
即可区分「新样式引入」与「重构前既有」。

| 现象 | 结论 |
|---|---|
| 空状态插图糊成近乎纯黑的色块 | **是主题层引入的，已修（两轮）**。第一轮 `base.css` 把 `--el-empty-fill-color-0..9` 改成 `color-mix(主色 N%, transparent)`，半透明色阶叠不出插画层次，插画糊成一团。第二轮改为**往不透明基底里掺主色**：`color-mix(in srgb, var(--v-primary) N%, var(--v-ramp-base))`，N 由 2% 递增到 24%。基底 `--v-ramp-base` 浅色下是白、深色下是页面底色，而 EP 的色阶方向恰好也是浅色由亮到暗、深色由暗到亮，同一组比例在两种配色下都成立，不必分叉。另加一条中性黑投影，避免浅色毛玻璃卡片上发飘 |
| `任务 → 定时验证计划` 表格「操作」列第三个按钮掉到第二行、`下次运行` 时间戳被 `fixed="right"` 覆盖 | **既有问题（非本次引入），未改**。该表各列最小宽度合计约 1100px，1280 宽窗口下可用区约 1024px，横向溢出约 76px：溢出导致 220px 的「操作」列放不下三个按钮（按钮总宽 188/190px + 2×12px 间距 > 220−24px），同时冻结列永久遮住 `下次运行` 右端约 76px。两种主题状态下的按钮 `top` 值完全一致，与主题层无关。纯 CSS 无解，需要重新分配列宽（属视图层改动，未动）。**注**：冻结列遮住 `下次运行` 这一点已由「固定列必须自带不透明底」那条规则改善——现在是**干净遮盖**（不透字），但「盖住」本身仍在；三个按钮换行的问题与主题无关，仍未动 |

### 固定列（`fixed`）必须自带不透明底

Element Plus 2.x 的 `fixed="left"/"right"` **不是**另起一张克隆表，而是给该列的 `th/td` 打上
`el-table-fixed-column--left/right` + `position: sticky; left/right: 0`。这意味着：**只要所有列宽
之和超过滚动容器**（或用户横向滚动过），这一列就会从自然位置**左移**，压在相邻列**上面**——
重叠是必然的，不是 bug。

EP 自己给这类列的规则是 `background: inherit`——继承所在行的底色，等于**假定行是不透明的**。
但本项目的主题为了让表格融进玻璃面板，把 `--el-table-bg-color` / `--el-table-tr-bg-color` 都设成
`transparent`（`base.css`）。于是覆盖层变成一层「半透膜」：被压住的文字会**从按钮后面透出来**。

症状是「云主机实例列表」里「实例」按钮显示异常（`tmp/cdp_list_rowactions.mjs` 可复现）：
「地域列表」列宽 地域 ID 120 + 名称 120 + 接入点 220 + 操作 190 = 650 > 弹窗可用 562，
`el-scrollbar__wrap` 的 `scrollWidth 650 > clientWidth 562` → 220px 的「接入点」列（x 599→819）与
190px 的「操作」列（x 731→921）**重叠 88px**，而操作列 `background-color: rgba(0, 0, 0, 0)`，
字符串 `…aliyuncs.com` 的半截就压在绿色「实例」按钮上。鼠标悬停时更糟：EP 的悬停规则
（`.el-table--enable-row-hover .el-table__body tr:hover > td.el-table__cell`，特异性 **0-4-3**）
把 **td** 换成半透明 hover 色，半透膜又回来了。

修法（`base.css` 7.1 段）：按表格所在的**那层表面**把覆盖列底色**压平**成不透明——
`background-color: <不透明底>` 再叠一层 `background-image: linear-gradient(<半透明色>, <半透明色>)`，
整体不透明、视觉上等价于「半透明色叠在不透明底上」。表面色用 CSS 变量分派：
`.el-dialog .el-table` 用弹窗底 `--v-bg-overlay`（各主题均为实色）；
`.el-card .el-table` 用 `--v-bg` + `--v-glass-bg`（玻璃卡片色多数主题带 alpha，故压两层）。
悬停态必须**再压平一次**（hover 色 → 表面色 → 不透明底三层），否则鼠标一上去又漏。
修复后 sticky 单元格 `background-color: rgb(24,24,27)`（弹窗内）/ `rgb(9,9,11)`（卡片内），
悬停时保持不透明底 + `linear-gradient(hover)`。

> 注意 `color-mix()` 做不到这件事——它会把 alpha 平均掉，压不出不透明底。必须用
> 「实色底 + 半透明渐变过层」这个写法。
>
> 覆盖列仍然会**盖住**相邻列的内容（粘性定位的本质），本修法只保证「盖住 = 干净遮盖」而不是
> 「透出乱字」。要连内容一起看清，只能重新分配列宽让它不溢出（见下节「任务」表格的老问题）。

### 浮层的包含块：进场动画不能留 `transform`

`position: fixed` 元素的包含块默认是视口，但**只要某个祖先的 `transform` / `filter` /
`backdrop-filter` / `will-change` / `perspective` / `contain` 计算值 ≠ `none`**，最近的那个祖先就
成为它的包含块。而 `el-dialog` 的 `.el-overlay` 在本项目**渲染在 `.page` 内部**
（`overlayParentChain: [div.page, main.el-main.layout-main, section.el-container, …]` 且
`overlayInsidePage: true`，EP 未做 teleport）。

`.layout-main > *` 的进场动画曾是 `animation: v-fade-up … both`。`both` 会**保留末帧**——
末帧是 `translateY(0)`，计算值 `matrix(1, 0, 0, 1, 0, 0)`（≠ `none`），于是 `.page` **永久**成为
`.el-overlay` 的包含块：弹窗不再相对视口居中（偏移 `dx=83, dy=70`），遮罩也缩成 `.page`
的大小（`784×245`）而不铺满窗口——表现为「分组管理点『编辑』显示异常」。

修法：去掉 `both`（`base.css` 的 `.layout-main > *, .v-enter { animation: v-fade-up … }`）。
进场动画本来就只跑一次，不需要用 `both` 保持末帧。去掉后 `.page` 的 `transform: none`、
弹窗 `dx=0, dy=-12`、遮罩 `1000×700` 铺满视口。

> 这与上面「浮层 popper 进场动画只动 `opacity`」是**同源**问题，都是 `transform` 动画的副作用：
> 一条是动画**期间**顶掉 popper 的内联 `translate3d` 坐标，一条是动画**结束之后**改变 fixed 后代的
> 包含块。统一结论：**`.layout-main > *` 及其任何祖先，都不能让 `transform` 的计算值长期 ≠ `none`**
> ——这也是为什么进场动画宁可只动 `opacity`。

### 对比度与可读性修复

下面四条都是主题层自身的缺陷（非重构前既有），已全部修复；对比度数值按 sRGB 线性化实算。

**1. 浅色主题的语义色与三级文字不到 WCAG AA。** 六个主题的 `--v-success/warning/danger`
最初直接搬 Element Plus 默认色盘的高饱和亮色（`#12a150` / `#d97706` / `#e5484d`），落在近白的
浅色底上只有 3.1~3.9:1；`--v-text-3` 更差（paper 的 `#8e939a` 仅 2.76:1）。已按**色相不变
压暗**逐主题换值，浅色语义色统一提到 4.6~5.4:1；`--v-text-3` 浅色提到 4.6~5.0:1、深色由
4.1~4.4:1 提到 5.5~6.2:1，且都保证与 `--v-text-2` 之间仍留一档，三级文字层次不乱。

**2. 深色主题下插件 logo 不可见。** 插件 logo 是后端下发的 `icon_image`，多数品牌标
（Simple Icons 那批）自身不带 `fill`，按 SVG 默认渲染为**纯黑**——留在浅色主题里没问题，
一进深色主题就跟底色糊在一起（OpenAI / Anthropic / Moonshot Kimi 约 1.1:1，等于隐形）。
第一版修法是 `base.css` 里统一给 `html.dark` 下的所有 logo 位垫一块 88% 白板，代价是彩色标
也被套上一圈白框，看起来像「背景没抠干净」。**现改为按 logo 逐个判定**：后端
`backend/icon_ink.py` 取不透明像素 `max(r,g,b)` 的 p90（SVG 则取其 `fill`/`stroke` 声明色——**含写在
`<style>` 里的 CSS 声明**，官方导出的 SVG 常用这种；判据是**可见度**而非 Rec.709 亮度，
后者会把饱和色——如纯蓝 `#0033FF`——误判成「糊」），低于阈值才算需要垫底，
`plugin_manager.icon_needs_lift()` 把结果随 `list_plugins()` 下发为 `icon_lift`；
前端只给置了该标志的 `<img>` 加 `.icon-lift`，`base.css` 的白板规则也据此限定。
**没有**在前端硬编码「哪几个标是黑的」——新装一个黑标插件同样自动纳入判定，不必改前端。
冷启动一次性分析约 76 ms（64 个插件 / 61 张 logo，34 张位图已从 640² 缩到 ≤256²、多数 128²），
之后按 `credential_type` 命中缓存（约 0.03 ms），缓存只在 `sync_plugins()` 时清空。

**3. 解锁页徽标外那圈旋转描边始终不可见。** 它原本是 `conic-gradient` 配 `radial-gradient`
圆形遮罩挖出的细环，两个几何错误叠在一起：遮罩 `closest-side, transparent 74% → #000 76%`
在 70px 的框上只有 **0.7px** 宽（亚像素，等于没画）；就算加宽，圆形遮罩套在圆角方块上也只能
切出横穿四角的彩边（结果就是一圈色散花边，像渲染瑕疵而不是设计元素），而且元素一旦 `rotate`
轮廓自身也跟着转，45° 时圆角方块会变成菱形。另一种方案是**同形状、只缩放不旋转**的描边扩散，
几何是对的，但挂的是 3.2s 无限动画——一个每次进来都静静扩散的环，信息量为零，只是让这一页
永远在重绘。**现为一圈静态描边**：圆角半径与外框同心，几何天然对齐，也不依赖
`mask-composite` / `@property`，任何内核都稳。

**4. paper 主题解锁页背后那团光晕渲染成一块带硬边的灰印。** 光晕原本硬编码
`color-mix(--v-primary 16%, transparent)` + 660px。两个原因：paper 的主色是近黑 `#2b2f36`，
铺开只会在米白纸上留一圈灰印；而 660px 的光晕在 `closest-side` 的 72% 处就到透明，透明边界
约 237px，恰好压在卡片边缘（半宽 230px）上，于是光晕几乎全被卡片盖住，只剩轮廓外一圈极窄
的灰边。现把颜色抽成 `--v-halo-1` / `--v-halo-2` / `--v-halo-opacity` 三个令牌（各主题可换色
或整体压淡，paper 换成本主题的陶土/鼠尾草色并把不透明度压到 0.5），尺寸放大到 900px，透明
边界约 324px、渐隐带约 90px，才散得开。同批把 paper 的三团 `--v-mesh-*` 背景球从 0.85 压到
0.35——0.85 在这张近乎白的纸面上叠出来像一层擦不干净的黄渍。

## 与 Python 后端通信

pywebview 将 Python 对象注入为 `window.pywebview.api`，所有方法均为 `async`：

```javascript
// 调用后端方法
const result = await window.pywebview.api.list_credentials({ group_id: 1 })

// 监听后端推送事件
window.addEventListener('vault:credential_updated', (e) => {
  store.refreshCredential(e.detail.id)
})
```

> **开发模式**：Vite dev server（:5173）+ pywebview 连接 localhost
> **生产模式**：`npm run build` → `frontend/dist/` → pywebview 加载本地文件

### Web / CLI 模式的桥接（`public/web-bridge.js`）

同一份前端产物也由 `backend/web_server.py` 通过 HTTP 提供。服务端在 `index.html` 里注入
`window.__KEYREALM_WEB__ = { token }` 并先加载 `web-bridge.js`：

- `window.pywebview.api` 用一个 `Proxy` 映射到 `POST /api/call`（Bearer Token），
  页面里的调用方式完全不变。注意 `then/catch/finally`/Symbol 属性必须返回 `undefined`，
  否则 `Promise.resolve(api)` 会把它当 thenable、调用一个不存在的 `then` 后端方法。
- 后端 `push_event()` 通过 `/api/events` SSE 下发，桥接层还原成同名 `CustomEvent`。
- 桌面专用方法在桥接层单独处理：
  - `open_external_url` → 白名单内 `window.open`
  - `open_log_file` → `/api/log_file`
  - `pick_save_path` → 后端 `web_pick_save_path` 分配临时路径，动作完成后 `/api/download` 取回并触发下载
  - 备份导入 → 浏览器文件选择；导出 → Blob 下载
  - 托盘 / 开机自启 / 轻量模式 / 关闭行为 → 返回“不支持”或 no-op
- 界面据此隐藏无意义项：顶栏「最小化到托盘」、设置里的「窗口与关闭」「启动」卡片；
  「关于」显示「Web 模式（浏览器）」。
- 开发模式（`npm run dev`）仍然使用内存 Mock，不会加载 Web 桥接层。

> 下文中出现的 `data/...` 路径均指**当前数据目录**（默认 `<程序入口>/data`，可通过
> `keyrealm.conf.json` 或 `--data-dir` 改动）。日志、任务、备份、下载临时目录都随之移动。

### 开发模式的内存 Mock（`src/api/mock.js`）

没有 pywebview 的普通浏览器里跑 `npm run dev` 时，`installDevBridge()` 会把一个**纯内存后端**
装到 `window.pywebview.api` 上（主密码 `demo1234`），让所有页面与交互都能走通。
三条必须守住的约束：

- **方法名与签名必须和主进程一致**：mock 直接冒充 pywebview 桥，所以它的键是**后端 IPC 名**
  （`list_proxies` / `set_tree_order` / `test_proxy_id` …，不是 `index.js` 里的驼峰包装名），
  参数顺序也要与 `main.py` 的 `VaultApi` 逐一对齐——桥接只走位置参数，错位不会报错、只会拿到错值。
- **返回值要贴合后端语义**：同样受 `call()` 的 `unwrap()` 约束（`{ok:false}` / `{error:…}` 被当失败抛出）；
  空值语义也要一致，例如代理 id 是 **32 位十六进制串**、`set_global_proxy(null)` = 直连、
  全局为直连时 `test_proxy_id()` 只测直连（`proxied` 为 `null`）。
- **插件目录不许手写**：`MOCK_PLUGINS` / `PLUGIN_ICON_IMAGES` 两份产物由
  **`scripts/gen_mock_assets.py`** 从 `plugins/` 现扫生成（含类别名/图标/字段表/`batch_verify`/
  `has_actions`/`icon_lift`），**加了插件就重跑一次脚本**：

  ```bash
  .venv/bin/python scripts/gen_mock_assets.py
  ```

  这两份数据以前是手写示意样本，很快就漂了（漏插件、编造不存在的插件、类别放错、
  `credential_type` 写成猜的），dev 模式的症状是「页面上少了几个插件 / 搜索搜不到 / 下拉里没有」。
  产物刻意保持**确定性**（不写时间戳、按 `credential_type` 排序、`id` 顺序分配），
  没改插件时重跑不会产生 diff。

  **不用记着手动跑**：仓库自带 `pre-commit` 钩子（`scripts/git-hooks/`），
  提交只要动到 `plugins/` 或该生成脚本，就会自动重跑并把产物一并暂存：

  ```bash
  .venv/bin/python scripts/install_git_hooks.py   # 每个克隆装一次（写本仓库的 core.hooksPath）
  ```

  钩子在「解释器/依赖缺失、生成脚本报错」时**只警告不拦提交**——不让一个 dev-only 产物
  把正常提交卡死；需要临时绕过时用 `git commit --no-verify`。

> mock 由 `import.meta.env.DEV` 守卫，**生产构建里被完全摇树移除**——改完可对比 `dist` 的 JS 哈希与
> 体积是否变化来确认它确实没被打进去（插件目录 + 图标共约 280 KB，只服务 dev）。

### 3. 凭据管理（Credentials）

左侧为插件目录树（与 `plugins/` 文件系统层次一致：类别 → 服务子插件），
点击类别节点显示该层级及其子层级的全部条目，点击服务节点按类型过滤；
右侧为凭据表格。**表头可拖拽调整列顺序**（顺序持久化到 localStorage）。

表格列：凭据（图标 + 名称 + 掩码敏感值副标题，如 `sk-123…cdef`）、类型、备注、
附加信息（余额等 account_info）、分组、状态、添加时间、最后验证、最后有效、操作。

**「附加信息」每个字段各占一行**：`extraLines(row)` 把 `status_detail.account_info` 摊成字符串数组
（`balance` / `usage_rate` / `organization` 有专门格式化且固定在前；其余键按
`ACCOUNT_INFO_PRIORITY` 排序后**逐个成行**），模板用 `.extra-line` 逐行渲染，`title` 用 `\n` 连全文。
**不再截断条数**（旧版是「最多 2 条、用 ` · ` 拼一行」）；`null` / 空串 / 对象或数组值仍跳过
——后者是插件把数组塞进 `account_info` 时前端无法渲染的原因（如 Google 的 `authorized_domains`），
所以**「只留账号」这类要求应当落成「让 account_info 里只剩一个标量键」**，而不是删前端逻辑。
键没有中文标签时会显示**原始英文键**，新增可读字段记得往 `Credentials.vue` 的
`ACCOUNT_INFO_LABELS` 里补一条（服务账号类的 `client_email` / `project_id` / `private_key_id` /
`firebase_state` / `hostingSite` / `token_expires_in` 已补）。

**行高三档**：备注与附加信息**允许换行**，但行高由工具栏的「行高三档」统一控制 ——
**紧凑 / 标准 / 宽松**（值 1 / 2 / 3，**默认「标准」**）。实现是给凭据表挂一个 CSS 变量
`--cred-row-lines`，`.cell` 加 `min-height: calc(1.5em * var(--cred-row-lines, 3))` 保证**所有行等高**，
`.cell-ellipsis` 用 `-webkit-line-clamp` 截断超出部分（悬停由元素自带的 `title` 显示全文）。

> **变量值是「该行能容纳的文字行数」，档位 N 对应 N+1 行**（模板里写 `rowLines + 1`）：
> 「名称」列天生就占两行（`.credential-name` + `.credential-sub`），所以档 1 必须等于现状的 2 行，
> 逐档 +1 行 —— `min-height` 以行数为单位，若直接把档位当行数，档 1 与档 2 都会低于名称列的自然高度
> 而**完全一样高**（58 / 58 / 78px）。改成 N+1 后为 58 / 78 / 98px，每档正好 +1 行。
>
> **变量只绑在凭据表上（`class="cred-table"`），绝不绑 `.page`** —— `el-dialog` 渲染在 `.page` 内部，
> 绑上去会连带改掉操作弹窗里两张表的行高。档位存 `localStorage['vault.credentials.rowLines']`，
> 过 `normalizeRowLines()` 规整（只收 1/2/3，其余落回默认），与其他 `vault.credentials.*` 同一套纯前端偏好。

> el-tag 的文字在 `.el-tag__content` 里，需单独压一层，否则分组名长了照样撑开。

**「状态」列与派生状态「插件禁用」**：入库的状态有四个——`valid` 有效 / `invalid` 失效 /
`error` 错误 / `unknown` 未验证（文案与配色见 `utils/format.js` 的 `STATUS_TEXT` /
`statusTagType()`，由 `StatusBadge.vue` 渲染）。此外还有一个**不入库的派生状态**
`plugin_disabled`「插件禁用」：该条凭据**所属插件被禁用**时，显示状态盖过库里的值改成
「插件禁用」，悬停提示「插件『X』已被禁用，该凭据暂时无法验证；可在『插件管理』中重新启用」
（不再回显库里那条已经过期的验证结论）。

> **为什么派生而不入库**：插件启用/禁用只是 `plugins/.state.json` 里的一个开关，可随时来回切。
> 若把 `plugin_disabled` 写进 `credentials.status`，重新启用插件后这些凭据就永远停在「插件禁用」
> ——成了洗不掉的脏数据。派生则跟着插件状态自动回弹。
> 实现是 `Credentials.vue` 的 `effectiveStatus(row)` / `effectiveStatusDetail(row)`，
> **表格状态列与状态排序都走它**；排序权重 `STATUS_ORDER` 里 `plugin_disabled` 排**最后**
> ——那是「暂时动不了」，不是「有问题等你处理」，不该混进异常堆里挡住真正要看的行。
> 状态**筛选**下拉里没有这一项：那个下拉的取值是直接递给后端做 SQL 过滤的，派生状态在库里查不到。

**排序**：工具栏上是**两个下拉**——「排序依据」（添加时间 / 名称 / 状态 / 最后验证 / 最后有效 / 分组）
与「升序 / 降序」，默认 `created_at` + 降序（= 最新添加的在前）。
分别存 `localStorage['vault.credentials.sortField']` / `['vault.credentials.sortDir']`，
只影响展示顺序（`sortedCredentials` computed），不动后端数据，与「列顺序 / 列可见性」同一套纯前端偏好。
中文名用 `Intl.Collator('zh-Hans-CN', { numeric: true })` 比较，避免按 UTF-16 码点乱序。

> 实现上每个排序依据只写**升序方向**的比较函数（`SORT_COMPARATORS`），方向由外层统一乘 ±1；
> 「状态」的升序即「异常优先」（`invalid` → `error` → `unknown` → `valid` → `plugin_disabled`；
> 末位那个是派生状态「插件禁用」，见上）。

**分页**：列表默认**每页 10 条**，预设 **5 / 10 / 20 / 50**，但下拉允许**手输自定义条数**
（`filterable` + `allow-create`）。控件在**筛选框**里（与「搜索 / 分组 / 状态」同一个 `el-card`，
不是底部）并**整体靠右**（`.pager` 用 `margin-left: auto` 推到右边缘）：最右是「**← / →**」翻页按钮
夹着「当前页 / 总页数」，其左才是「每页 xx 条」下拉。每页条数存
`localStorage['vault.credentials.pageSize']`；**当前页不落盘** —— 页号是「当前看到哪儿」，
下次启动还停在第 5 页只会让人以为列表少了内容。分页是**纯展示层**：筛选走后端、排序在前端 computed，
所以实现只是对 `sortedCredentials` 切片（`pagedCredentials`），**不动后端查询**。

> 每页条数的三个来源（预设下拉 / 用户手输 / localStorage 旧值）都过 `normalizePageSize()`：
> 正整数才收，`0` / 负数 / 字母 / 空一律回落 10。**手输**这条尤其要规整 —— `allow-create` 回传给
> `v-model` 的是**字符串**（`"37"`），而且用户填 `0` 时若不拦，`slice(0, 0)` 会让表格直接变空；
> 拦下来退回默认值后还要 `ElMessage.warning` 明说一句，否则用户只看到自己填的数「被界面悄悄改了」。
> 单位「每页 / 条」写在选择框**外面**：`allow-create` 造出的选项 label 就是用户输入的原文，
> 若把单位塞进预设项的 label，自定义值就会显示成光秃秃的「37」，两种形态混在一处很难看。

> 三条配套规则：
> ① 换筛选条件（搜索 / 分组 / 状态 / 目录树选类别）一律**回第 1 页** —— 那是另一批数据，停原页没意义；
> ② 排序**不回第 1 页** —— 顺序变了但总条数不变，留在原页更符合预期；
> ③ 条数变少（删除 / 筛选命中更少 / 调大每页条数）时靠 `watch(totalPages)` 把当前页**夹回**合法范围，
> 否则会停在一个空页上（如删掉某页最后一条后仍停在第 5 页，而总共只剩 4 页）。
> 夹回必须写在 `watch` 里而不是 `computed` 里 —— 在 computed 中改 ref 是反向依赖，会触发 Vue 的递归更新警告。

> 分页**只切表格要渲染的行**，不改「当前列表」的语义：别处（如「批量验证」「批量删除」的勾选清单）
> 取的仍是筛选后的**全量** `vaultStore.credentials`，不是当前这一页 —— 否则「全选」会变成「选中本页」。

**逐条验证的并发保护**：验证状态记的是一个 **id 列表**（`verifyingIds`）而不是单个 id——否则
点了 A 再点 B，A 的按钮会重新变可点，同一凭据被重复验证、白打两倍请求。前端在 `verifyRow`
入口再查一次「已在验证中」直接忽略；后端 `scheduler.verify_single_credential` 也有一层
**同 id in-flight 拦截**（重复请求直接返回「该凭据正在验证中，请稍候」），两层兜底。

**「操作」按钮常驻**：「操作」与「验证」是操作列里唯一两枚**依赖插件能力**的按钮，
「编辑」「删除」是纯本地数据操作，插件禁用与否都照常可用。

- 按钮**不按「有没有操作」显隐**，一律渲染：插件没声明 `actions()`（或声明了但返回 `[]`）时
  按钮仍在，只是**置灰**，悬停提示**「暂无可用功能」**。原本的做法是 `v-if="…has_actions"`
  直接隐藏，于是同一列里「有操作的行」多一枚按钮、「没操作的行」少一枚，**每行的按钮位置都对不齐**。
  判断依据是插件记录的 `has_actions`（后端 `list_plugins()` 写入，= 模块存在且声明了 `actions`）。
- 置灰与提示由 `actionHint(row)` 一处收口：插件禁用 → 「插件已禁用」；插件启用但无操作 →
  「暂无可用功能」；两者皆非 → 空串（`el-tooltip` 的 `:disabled` 随之关闭，不弹空提示）。
  `canOpenActions(row)` = `!batchLocked && !actionHint(row)`，即整页互斥（批量验证进行中）也走同一道闸门。
- ⚠️ **`el-tooltip` 不能直接包 disabled 的 `el-button`**：浏览器对 disabled 控件不派发鼠标事件，
  提示永远不弹。两枚按钮**各自**包一层非 disabled 的 `span.action-anchor` 作锚点
  （`inline-flex` 贴合按钮，不影响 `.action-cell` 的 flex 间距），因此各有各的提示文案。

**「操作」弹窗**（插件可选能力，见 [PLUGIN_GUIDE.md §3.1](PLUGIN_GUIDE.md)）按 `kind` 分三支：

| kind | 呈现 |
|------|------|
| `chat` | 对话气泡；模型下拉**常驻一个「获取/刷新模型列表」按钮** |
| `form` | 动态表单 + `<pre>` 文本输出；`write: true` 时提交前二次确认 |
| `list` | **表格 + 行内按钮 + 下钻**：工具栏有面包屑与「返回」「刷新」，行内按钮由 `row_actions` 声明 |

> **带进度的操作**（action 声明 `progress: true`，如 OSS 下载 / 前缀打包）：表单弹窗改走
> `api.streamCredentialAction`，后端在下载过程中推 `vault:action_stream` 的
> `{stream_id, progress:{current,total,text}}`，`handleActionStream` 把它渲染成 `el-progress`
> （`total <= 0` 时用 `indeterminate` 走动画）。终态仍由同一条 `done` 事件收口：非 chat 的弹窗
> 把 `output` / `error` 写进表单弹窗并结束 `busy`。

- **多个操作时**先弹选择菜单（`.action-menu`，固定定位，全局一份，不给每个表格行挂下拉）；
  **只有一个操作时直接进**，保住原有的一键体验。菜单先按 `actions` 全列出，**权限探测结果回来再收敛**
  （避免「先显示后消失」的抖动）。
  - 菜单项**只显示功能名**，不渲染 `description`（避免列表被解释文字撑长）。
  - 菜单外**点一下就关**（菜单自带的点击遮罩 `closeActionMenu`）；不选也得能关掉。
  - 菜单**贴到视口右/下边缘会自动回退**（`placeActionMenu()`：渲染后量实际尺寸，右侧放不下就
    左移、下方放不下就翻到锚点上方，权限探测把条目收敛后高度变化会再贴一次），并带
    `max-height` + 滚动兜底——列表底部的条目点「操作」不会再被裁掉。
  - **纯下钻操作不进菜单**：某个 action 只被别的 action 当 `row_action` 目标、自身又没有 `fields`
    时，从顶层菜单隐去（否则点进去只会得到「缺少 xxx」）；它仍照常被行内按钮调用。
    判定见 `rowOnlyActionIds()`。
- **权限探测**：点「操作」时懒加载 `api.credentialCapabilities(id)`，会话内按凭据缓存（**不落 localStorage**）；
  没权限的操作被隐藏，一个都没有时用 `ElMessageBox.alert` 显示插件的 `note`。
  探测失败 → fail-open（全都展示），三种状态互不混淆。
- **列表的加载/空/错**三种态各有表现：`v-loading`、表格 `#empty` 插槽（用插件的 `empty_text`）、
  出错时 `el-alert` + 「重试」且**不关弹窗**。
- **行内动作**：`$row.<列key>` 模板解析不到的行**按钮置灰**（绝不把 `undefined` 发出去）；
  目标是 `form` 就打开表单预填、是 `list` 就下钻（下钻用**栈**保存上一帧，返回时零请求还原）。
  > 下钻/预览的**首次**请求必须直接用本次传入的 `params`。`openList` 里 `actionDialog.value`
  > 被整体换成**新对象**，而 `const dialog = actionDialog.value` 取的仍是**旧对象**——
  > 若末尾用 `dialog.listParams` 会拿到上一次（首次为空）的参数，表现为「第一次提示缺少参数、
  > 点一下刷新才好」（GitHub「详情」、OSS「预览」、进入目录要连点两次，属同一原因）。
  > 下钻时凭据名随对话框一路带着：`runRowAction` 不回头查凭据列表，而是把
  > `actionDialog.credentialName`（在 `openList` / `openAction` 首次打开时从 `cred.name` 落进去）
  > 传给 `openList` / `openAction`。否则只传 `{ id }` 会让标题渲染成「云主机实例列表 ·
  > `undefined`」。
- **操作表单的必填校验**：`form` 类的表单与 `list` 类的内联参数行**共用** `actionFormFields`，
  两处的 `<el-form>` 都挂了 `ref="actionFormRef"` + `:model="actionDialog.values"` + `:rules="actionRules"`，
  每个 `el-form-item` 带 `:prop="field.key"`。`actionRules` 由插件的 `fields[].required` 生成
  （trigger：select/checkbox → `change`，其余 `blur`），提交前 `runActionForm` / `refreshList`
  各自 `await validate()`，不过就停在原地（红星与错误提示才是给用户的反馈，不该悄悄跑掉）。
  > 两处 `<el-form>` 复用同一个 `ref` 是安全的：`form` 与 `list` 是 `v-else-if` 分支，**不同时挂载**。
  > 加 `prop` 之前这两处**既无红星也不校验**（插件声明了 `required` 也形同虚设），而
  > 「新增 / 编辑凭据」表单一直是有红星与校验的（`CredentialForm.vue`）——两边口径现在才对齐。
- **下载类操作**（`save_to`）：顺序是**先确认（若 write）→ 弹「另存为」→ 把路径塞进 `params` → 调插件**。
  路径不是秘密，而不是把带鉴权头的下载 URL 交给前端——那等于把短期凭证递给 JS。

**模型列表常驻**：按钮**一直显示**（已拉到过就是「刷新模型列表」），列表按凭据缓存在会话里，
重开对话框不必再等网络；拉到后**只在用户没选过时自动取第一个**，**已有选择绝不覆写**；
拉取失败保留原有列表与选择，只加一条 `modelError` 提示。

**新增/编辑凭据表单**（`CredentialForm.vue`）完全由插件的 `fields_schema` 驱动：
`checkbox` → `el-switch`、`select` → `el-select`、`number` → `el-input-number`、
`model` → **可下拉可自由输入**的 `el-select`（`filterable` + `allow-create`，候选来自
`list_draft_models`，取不到也照样能手打模型名）、其余 → `el-input`（`password` 带 `show-password`）。

> `select` 的 `options` 由 `utils/format.normalizeOptions` 归一，**两种写法都支持**：
> 纯字符串数组（值与显示都用它）、或 `{value,label}` 对象数组（显示 label、存 value）。
> 三处渲染（CredentialForm / Credentials 的操作弹窗表单 / ScopeDefaultsDialog）共用同一套，
> **不要写回只认字符串的版本**——否则想给用户看中文就只能把中文当值存进库。
>
> 字段的**条件显隐**由 `utils/format.visibleFields` 统一求值（manifest 的 `show_if`）：
> 只渲染当前模式命中的字段，且**提交时也只带这些字段**（`buildData` 走 `visibleSchema`），
> 免得切模式后另一组密钥还留在库里。三处渲染同样共用——见 OpenAI 插件的 `auth_mode`。
字段可带可选 `hint`（manifest 字段），渲染为字段下方的灰字说明；`sensitive` 字段额外标注
「加密存储」。LLM 类凭据的「余额未知时发一次对话探测」开关与「探测模型」就靠 `hint` 解释用途
——它是**凭据级**配置，不在系统设置里，见 [PLUGIN_GUIDE.md §2.4](PLUGIN_GUIDE.md)。

**框架注入的「使用代理」**：表单末尾多一项三选一（`components/ProxySelect.vue`）——
**跟随上层设置 / 直连 / 指定某个已保存的代理**，值写进凭据 data 的两个保留键
`_proxy_mode` + `_proxy_id`。其中「跟随上层设置」那项会**括注实际会走哪个出口**
（由后端按「该插件预设 > 所属类别预设 > 全局」解析好，来自 `get_credential_defaults` 的
`inherited_proxy`）——否则用户对着「跟随上层」根本猜不到是哪个。插件不支持代理时（如 `mail_smtp` 用标准库 smtplib，
后端按「有没有 `make_client`」判定）该项**不显示**，免得白设。

**新建时的默认预填**：打开新增表单（或切换凭据类型）时调 `api.getCredentialDefaults(type)`，
把该插件的默认设置填进空字段。**唯一例外是代理**——它不预填（见上），因为预填等于把预设
烤成「条目设置」，之后改插件/类别预设就对这条凭据不再生效。

把该插件的默认设置填进空字段——默认值按「**插件级 > 类别级 > manifest 的 field.default**」
继承。**编辑时不套默认**，否则用户显式清空的字段会被复活。

**类别 / 插件默认设置的入口（两处，共用一个对话框 `ScopeDefaultsDialog.vue`）**：
（对话框里的代理项文案是「**不在此层指定**」——那是相对这一层而言的，不是「跟随全局」）
① 「凭据目录」树上右键**类别节点**或**服务节点**（类别节点原本不可右键，现已放开）；
② 「插件管理」页每个类别标题 / 插件行上的设置按钮。对话框把当前值与可预设字段列出来，
底部可「清空」。

> 左侧为「凭据目录」树（可拖拽调宽、带搜索），选中节点即按类别/服务过滤。
> **右键节点**弹菜单：**类别节点**给「类别默认设置」，**服务节点**另有「禁用插件」/「启用插件」
> （按当前状态切换；禁用**不动磁盘目录**，其凭据照常保留、状态显示为「插件禁用」，
> 依赖插件的功能选项置灰）。
> **节点顺序可拖拽调整**：按住节点拖到同级目标的前/后即改顺序，顺序落 `settings.tree_order`
> （不是 localStorage——同一份顺序要在别的机器、别的客户端上也成立）。**只做同级排序**：
> 类别与类别、插件与插件，落点校验 `allowTreeDrop` 拒掉 `inner` 与跨父节点，因为「把插件拖进
> 另一个类别」等于改磁盘上的插件目录，不在本功能范围；类别与插件也不能混排（未归类的插件与
> 类别节点同处一层）。类别的 `category` 键可能是**空串**（「未归类」桶），那是合法条目。
> 存的是**顺序清单而非快照**：只记用户排过的那些键，新装的插件不在清单里，由前端按自然顺序
> 追加到末尾，所以后续增删插件不会让这份顺序失效。拖拽期间保存失败会**回滚**到原顺序并提示。
> 「恢复默认顺序」按钮仅在存在自定义顺序时出现，点了**弹二次确认**（破坏性），确认后写入空清单。
> 树的**展开/收起**由本组件维护（`expandedKeys` 持久化到
> `localStorage['vault.credentials.treeExpanded']`），再通过 `:default-expanded-keys` 交回 el-tree
> 在重建时恢复。**两个必须注意的约束**：**(1)** `:auto-expand-parent` **要显式关掉**——el-tree 默认
> `true`，而 `setDefaultExpandedKeys` 会对它列出的**每个**节点调 `expand(null, autoExpandParent)`，
> `expandParent` 会把该节点的**所有祖先一并撑开**；类别节点的祖先就是根「全部凭据」，于是只要下面
> 还有任一类别在 `expandedKeys` 里，用户收起根之后立刻被顶回来（表现为「『全部凭据』怎么都收不起来」，
> 而类别本身不受影响，因为它的子节点是叶子、从不进 `expandedKeys`）。**(2)** 记录展开时要**赋新数组**
> 而非原地 `push`：el-tree 判 `default-expanded-keys` 变化用的是数组**身份**（`hasChanged`），原地改
> 不触发 watcher，`store.defaultExpandedKeys` 停在旧值，下一次 treeData 重建时刚展开的节点会自己收回去。
> **右键菜单**是 `position:fixed` 落在光标处，渲染后按自身尺寸**回拉进视口**（`clampCtxMenu`，
> `nextTick` 后量 `offsetWidth/offsetHeight`）——否则右键点在窗口右/下边缘（最常见：列表**最后一项**）
> 时菜单会被裁掉一半。贴边只回拉、**不翻转**：条目少、不会挡住内容，回拉比「贴底就往上弹」更好预测。
> 「批量验证」按钮会弹出**手动勾选对话框**（列表当前列表内凭据、支持「全选」），
> 勾选后按所选凭据 ID **并发**验证；`batch_verify=false` 的类型（有写副作用或无法自动化）
> 在弹窗中禁用勾选、标记「需手动验证」，只能逐条点「验证」；被禁用插件的凭据同样禁用勾选，
> 但标记为「**插件已禁用**」以区分两种不可批量验证的原因。

**批量验证对话框的运行参数**：对话框顶部有两个 `el-input-number`——**并发线程数**与
**超时（秒）**。打开对话框时调 `get_batch_options` 回填上次保存的值，同时取回取值范围
（并发 1–32，超时 5–300 秒）；点「验证」时两个值随本次验证一起提交并落库
（`settings` 表的 `batch_concurrency` / `verify_timeout`），下次打开沿用。
边界由后端下发，前端不硬编码常量——见 `backend/verify_options.py`。

**点「验证」之后：后台跑，界面不阻塞**

- 顶部出现一条**非阻塞横幅**：运行中显示 `正在批量验证 12/83 · 当前：<凭据名>` + 「查看任务」按钮（直达 `/tasks`）；
  手动以外的来源会照实说明（`定时批量验证进行中` / `MCP 触发的批量验证进行中`）。
  完成后同一位置变成结果摘要（`批量验证完成：有效 73 · 无效 0 · 异常 7（跳过 3）`，有异常用 warning 色；被取消时显示
  `已取消（已处理 n/m）`），可手动关掉。
- **不再用模态弹窗**：以前是一个不可关闭的 dialog，等于把整个界面按在前台、切页都做不到。
  现在横幅只提示，用户可以照常切页、看别的凭据、去「任务」页看进度。
- **被测条目**的「验证」按钮转为 loading 且不可点——id 列表由 `vault:batch_verify_started` 下发，
  避免同一条被重复触发。**只有本次涉及的条目被禁用**：勾了 A/B/C，D 的按钮照常可用，想单条补验就补验。
- **整页只读只发生在手动批量**：`batchLocked = running && trigger === 'manual'`（trigger 由
  `vault:batch_verify_started` 下发，取值 `manual` / `mcp` / `schedule`）。手动是用户自己点的，
  知道在跑，锁上新增 / 编辑 / 删除 / 行内「操作」才不会「验证没结束就把条目改掉，结果与界面对不上」；
  **定时任务与 MCP 触发不锁页**——那是用户没看着的时候跑起来的，把界面冻住只会让人莫名点不动。
  两种情况下**都不禁导航**——用户就是要能在后台跑的同时去「任务」页。
  「批量验证」按钮与对话框内部（全选 / 勾选 / 确认）则一律用 `batchRunning`：任何一批在跑都不允许再起第二批。
- 进度与**取消**都在「任务」页（批量验证会登记成一条 `kind=batch_verify` 的任务；取消是协作式的，
  见 ARCHITECTURE §2.4）。

**批量删除**：工具栏的「批量删除」按钮（`type="danger"`）复用**与「批量验证」完全相同的勾选对话框**，
差别只在破坏性操作的取向上：

- **默认全不选**（批量验证默认全选）。破坏性操作不替用户预勾选 —— 省下的一次点击，抵不上误删一整批的代价。
- **不置灰任何行**：删除是纯本地数据操作，插件是否禁用、能否批量验证都不影响能否删掉这条凭据；
  故对话框里没有「需手动验证 / 插件已禁用」这类标记，只多一条 warning `删除后不可撤销，请确认后再操作`。
- 点「删除 N 条」（0 条勾选时禁用）**再弹一次** `ElMessageBox` 二次确认
  （`确定要删除选中的 N 条凭据吗？该操作不可撤销。`），取消则什么都不做。
- 勾选清单同样取 `vaultStore.credentials`（当前树 / 筛选后的**全量**，跨分页），
  因此「全选」是整批而不是本页。
- 按钮与其他写操作共用整页互斥闸门 `batchLocked`（手动批量验证进行中置灰）。

一次 IPC 删一整批：`delete_credentials(ids)` 在**单事务**内删完并只推**一次** `vault:credentials_changed`，
store 随后重拉分组 / 插件。**不走「前端 for 循环调单条删除」**——那会变成 N 次 IPC、N 次事件、2N 次重拉，
且没有事务保证。结果提示以**后端返回的实际删除条数**为准（`{ok, deleted}`）：
期间有条目被别处删掉时会小于所选数，不谎报。

**添加凭据**：表单的「服务」下拉支持**关键词搜索**，选项按插件类别分组
（LLM / API 服务）。保存前自动做**重复凭据检测**——凭据值与既有凭据任一字段
相同即弹出确认框，用户可选择继续添加或取消。

> 「定时验证计划」原先也在这张页面上，现已挪到**任务页**（见 [§11 任务](#11-任务tasks)）——
> 它和后台任务是同一类东西（程序自己在后台干的事），用户找它时直觉是去任务页，而不是系统设置。

**「外观」** 是唯一的纯界面设置：`components/ThemePicker.vue` 把 `THEMES` 里的 6 套方案按
`mode` 分成浅色/深色两组铺成网格，点选即 `applyTheme()`。数据不出本机（localStorage），
与后端无任何交互，因此这一卡片连 loading / 错误态都不需要。

**「验证范围」共四种**：全部凭据 / 指定分组 / 指定类型 / **指定凭据**。前三种把目标写进 `target_id`
（多态字段：group 存分组 id，type 存凭据类型名）；「指定凭据」改用 `credential_ids`（凭据 id 数组）。
勾选界面**整体复用「备份 → 仅选中的凭据」那套目录树**——同一个组件
`components/CredentialTreePicker.vue`（类别 → 服务 → 凭据三层、可搜索、全选只勾当前可见项、
实时「已选 n / m」；定时计划里 `:max-height="200"`，备份页用默认 260）。
**「指定凭据」必须至少勾一条**：保存与「立即运行」都会被拦下并提示。原因是后端
`batch_verify(credential_ids=[])` 等同于「不带筛选」，会去验证**全库**——与「一条也不验」正好相反，
所以 `scheduler._run_schedule()` 对空勾选另做了短路（跳过 + 告警日志，并照常刷新 `last_run_at`）。

**「空闲自动锁定」**：下拉档位由后端下发（`api.getAutoLock()` → `options`），
选中即 `api.setAutoLock(minutes)` 落库（`settings.auto_lock_minutes`，0 = 关闭）。
计时完全在后端守护线程里，前端只负责两件事：**节流上报用户活动**
（`App.vue` 的 mousemove / mousedown / wheel / touchstart / keydown / focus / visibilitychange
→ `appStore.reportActivity()`，内部约 30s 节流一次），以及**收到 `vault:locked` 事件时锁定本页状态**
（`appStore.applyLocked()` → 清空明文 → `watch(appStore.unlocked)` 推回 `/unlock`）。
详见 [ARCHITECTURE.md §2.8](ARCHITECTURE.md)。

**「不锁定」**（`settings.never_lock`，默认关）：开启后 `idle_lock` 直接跳过空闲判定，
解锁/创建/改密时把当前密钥交给系统凭据保护（`backend/session_key.py`：Windows DPAPI /
macOS 钥匙串 / Linux Secret Service；Linux 无 Secret Service 时退化为 machine-id + 用户 +
数据目录派生的本机绑定加密文件），桌面/Web 启动时在常驻服务前自动恢复。**手动「立即锁定」
会删除持久化密钥**，重启后保持锁定；关闭该设置同样删除。CLI 是一次性进程，不读取持久化密钥。
前端开启时把「空闲自动锁定」置灰并提示不生效；持久化失败会在开关下方返回 warning。

**「立即锁定」** 与「空闲自动锁定」，以及托盘菜单的「锁定」，最终都走 `api.lock_vault()` 同一个出口，
因此在三种入口下界面表现一致（都会清空明文并跳回解锁页）。

**「轻量模式」**（`settings.light_mode`，默认关）：开关只落库，`api.setLightMode(bool)` 不动当前页面
——真正的行为在**下次最小化到托盘**时发生。开启后最小化会「释放界面」：后端把当前文档换成一张极小
的占位页（`Window.load_html`，见 [ARCHITECTURE.md §2.11](ARCHITECTURE.md)），释放掉整个 SPA 的
DOM 与 JS 堆；再从托盘「打开窗口」时后端 `load_url(<file:// 入口>)` 重新加载前端。

**「开机自启动」**（`backend/autostart.py`）：**只碰系统侧、不落 `settings`**。开关的取值来自
`get_autostart()` 现读的操作系统自启条目（Windows `HKCU\…\Run` 值名 `Keyrealm`、
Linux `$XDG_CONFIG_HOME/autostart/keyrealm.desktop`、macOS
`~/Library/LaunchAgents/com.keyrealm.app.plist`），开启 = 写条目、关闭 = 删条目。
**库里刻意不存副本**：用户手动删掉系统条目后两边就长期不一致，且没有时机能可靠重同步。
启动命令由 `launch_argv()` 按**冻结与否**推导（冻结 → 执行 exe 本身；源码 → `<python> main.py --gui`），
不写死本机路径，并固定追加 `--autostart`。桌面端启动时若带该参数且「关闭主窗口时」为
`background`，会在托盘可用时以 `hidden=True` 创建窗口——登录后直接驻留托盘、不弹出主窗口；
托盘不可用则回退为正常显示。启动时还会调用 `ensure_current()` 刷新旧条目，补上该参数。
开关旁显示系统落点（`target`）；平台不支持或写失败时面板置灰 / 报错（`AutostartError`
→ `{ok:false, message}`），前端按返回的 `enabled` 回写开关而非自行假设。

代价要在界面上说清（就是开关下方那行说明）：重新打开需要等界面重建；释放时未保存的编辑内容会丢；
**后台的 MCP 服务与定时任务完全不受影响**（它们和后端进程一样在跑，释放的只是前端渲染层）。

**代理一律按 id 引用**：`proxyStore`（`stores/proxy.js`）持有代理列表与全局默认；
「默认代理」下拉的值是 `proxy_id`（空串 = 直连），保存走 `api.setGlobalProxy(id)`。
列表里每项一个「测试」按钮 → `api.testProxyId(id)`（测全局则传 `null`），
结果区展示两列探测卡片（不挂代理 / 挂代理），每列三行（出口 IP / 国内站点 / 国外站点），
上方用 `el-alert` 给出 `ok / warn / fail` 三档结论。探测最多约 10 秒（直连国外站点要等超时）。

> **测试状态放在 store 而不是页面里**：`<router-view>` 没有 keep-alive，切到别的功能栏
> 组件就卸载了——后端其实已经跑完，结果却写进已销毁的实例，用户看到的现象是「测试被中断」。
> 放进 `proxyStore.testing` / `proxyStore.result` 后切页不丢（与批量验证同一套路）。

> **缺 SOCKS 依赖时**（env 无 `socksio` 却配了 `socks5://`）：后端不发代理探测，直接返回
> `fail` 结论，`el-alert` 显示「代理不可用：当前环境缺少 SOCKS 支持（socksio）」并附
> `pip install "httpx[socks]"` 的处理办法；右侧卡片照常渲染，三项显示「查询失败：未执行探测…」，
> 左侧直连数据仍然真实。避免把一句英文 `ImportError` 直接甩给用户。

日志相关配置（级别、条数、查看、清空）**已移出本页**，见第 7 节；
备份/恢复见第 9 节，版本信息见第 10 节。

### 8. 插件管理（PluginManager）

**一张卡片：插件列表**（按类别分组）。不再有「可添加（内置源）」卡片——`plugins/` 是插件的
**唯一事实来源**，发行包里有什么就是什么。行内按钮是**「禁用」/「启用」**，**无二次确认**。

**条目最左侧**是一枚定宽的状态标签，**「已启用」「已禁用」两种状态都显示**（绿 / 灰）：
按钮上的「禁用」/「启用」是**动作**（点了会发生什么），靠它反推当前状态容易看反；左侧竖着
扫一遍就知道哪些被关了。禁用行的弱化**只压名称与副标题的文字**（`opacity: .55`），
**不再整行 `opacity`**——整行透明度会把右侧那枚「启用」按钮一起压灰，看着像不可点，
而它恰恰是用户该点它来恢复的。

**禁用 / 启用的连锁效果**（前端）：

- 点击调后端 `set_plugin_enabled(credential_type, enabled)`；后端只推 **`vault:plugins_changed`** 事件，
  前端收到后重载插件列表（事件名不再有别的）。
- 凭据列表（`Credentials.vue`）里，被禁用插件的凭据**照常显示**，状态列显示**派生状态
  「插件禁用」**（盖过库里的值、不入库，见 §3 的说明）；由 `isPluginEnabled(credential_type)`
  判定，**只把「操作」与「验证」按钮置灰**并悬停提示「插件已禁用」，
  **「编辑」「删除」凭据仍然可用**。
- 点「编辑」这类凭据时，表单**照常渲染全部字段并带出已存的值**：编辑表单的字段 schema 取自
  `pluginByType`（**含已禁用插件**）而不是 `enabledPlugins`——禁用只关功能闸门，不改插件的
  数据形状。（若改用 `enabledPlugins` 取 schema，禁用插件的凭据一打开编辑就是一片空白表单——
  数据明明在 `form.data` 里，却没有输入框承载它。）
- **不允许给已禁用插件「添加凭据」**：目录树选中项指向已禁用插件时，点「添加凭据」**按钮不置灰**，
  但会明确提示「插件『X』已禁用，无法添加该类型的凭据；可在『插件管理』中重新启用」且**不打开表单**。
  选中**类别**时，默认服务会跳过该类别下已禁用的服务、取第一个可用的（新建表单的类型下拉本就
  只列已启用插件，所以选中一个可用类型后不会撞上这道闸门）。
- **批量验证**自动不含被禁用插件的凭据：前端批量勾选处有一道闸门（`Credentials.vue`），
  后端 `scheduler.py` 亦维护排除集，两处都按禁用插件过滤。
- 凭据页**目录树右键菜单**里，原来的「删除插件」改为**「禁用插件」/「启用插件」**（按当前状态切换）。
- 被禁用**且名下没有凭据**的插件，在**目录树里不再显示**。

**类别折叠**：63 个插件平铺太长，按类别分组 + **可点击折叠的标题**
（标题显示类别图标、名称与条数，如 `🤖 LLM 模型（18）`）。折叠状态存
`localStorage['vault.plugins.collapsedCats']`，刷新后保持；**搜索框有内容时忽略折叠、
强制展开所有命中类别**——否则搜到了东西却看不见，会让人以为没结果。
类别标题右侧留了 `.pm-cat-actions` 占位，给「类别默认设置」按钮用。

**搜索**（工具栏右侧 `el-input`，`clearable` + `Search` 前缀图标，宽 240px）：

- **实时过滤**（`v-model` + computed），不需要回车，也不请求后端——纯前端过滤已加载的列表。
- 匹配字段：`name` / `credential_type` / `description` / `category_name`，**大小写不敏感**；
  输入按空白拆成多个关键词时需**全部命中**（AND）。
- 过滤只影响展示，**不改动任何状态**：按类别分组渲染，**组内无匹配项时整组隐藏**（不留下空标题）。
- 空状态给「没有匹配的插件」（卡片保持，避免整体消失造成位置跳动）。

### 9. 备份（Backup）

两张卡片：**导出备份** 与 **导入备份**；页面底部用一条 `el-alert` 回显上一次操作的结果

导出有三组控件，两个维度**互不重叠**：

```
┌─────────────────────────────────────────────────────────────┐
│ 导出备份                                                     │
│  备份范围： (•) 全部凭据（含分组与偏好设置）  ( ) 仅选中的凭据 │

- **备份范围**：`all` = 全部凭据 **+ 分组 + 偏好设置**；`credentials` = 只有凭据。
  后端把「范围」与「勾选」当两个独立参数（`scope` / `credential_ids`），见
  [ARCHITECTURE.md §2.4](ARCHITECTURE.md) 的备份说明。
- **凭据勾选**：一个**目录树**（`el-tree` + `show-checkbox`），三层 = 类别 → 服务 → **凭据**，
  与「凭据管理」的目录树同源（都来自 `vaultStore.pluginTree`），只保留**有凭据**的服务节点。
  勾类别即全选其下凭据；只读叶子（`getCheckedKeys(true)`）再按 `cred:` 前缀取出真正的凭据 id，
  所以类别/服务节点不会混进选中集合。
  > **这一整块是一份共享组件**：`components/CredentialTreePicker.vue`。它同时被
  > 「任务 → 定时验证计划 → 指定凭据」使用（同一套勾选语义，各写一份必然长歪），
  > 差异只在树区高度（备份页默认 `260`，定时计划传 `200`）。勾选结果经 `v-model`
  > 以**凭据 id 数组**双向绑定到父组件。
  > **这里始终展示全部凭据**：数据来自 `api.listCredentials({})`（空筛选）后存进组件的**局部**
  > `ref`，**不**走 `vaultStore.credentials`。后者是「凭据管理」页按当前分组/关键词查出来的结果，
  > 两页共用同一个 store 会串味——在凭据管理里选中某个分组后，备份页的树会跟着只剩那一撮。
- **搜索**用 `el-tree` 的 `filter-node-method` 过滤；「全选」只勾**当前可见**的凭据
  （不会把被搜索隐藏的也勾上），右侧实时显示「已选 n / 总数」。**未勾选任何凭据时导出按钮禁用**。
- 空/加载/无结果各有文案（「正在加载凭据…」/「没有可选凭据」），避免出现空白框。

**导入卡片**：一句话说明语义——按**当前系统的插件字段表**填充，不覆盖既有数据。点「导入备份」
先弹一次确认（列出三种会导致**整条失败**的情形：插件未安装/已禁用、含当前插件不认识的字段、
缺少必填字段），确认后走 `api.importBackup()`（文件选择框在后端）。

导入结果**有失败或生成了日志就弹「导入结果」对话框**（`append-to-body`），否则只用一条
`ElMessage` 收尾：

```
┌ 导入结果 ─────────────────────────────────────────────┐
│ ⚠ 已导入 9 条，失败 3 条                              │
│ 失败条目（3 条）                                       │

### 11. 任务（Tasks）

长操作（下载 / 打包）的**后台任务**管理页：看进度、取消、清空已完成。侧栏「任务」项带
**进行中数量角标**（为 0 时不渲染，不占位）。

本页有**两张卡片**：「后台任务」与「定时验证计划」（后者原先在系统设置页，见下）。

```
┌──────────────────────────────────────────────────────────┐
│ 任务            每页 [10 ▾] 条  ‹ 1 / 3 ›   [ 清空已完成 ]│
├──────────────────────────────────────────────────────────┤
│ 打包下载 · 阿里云 OSS生产        进行中                  │
│ ████████████░░░░░░░░  62%   3/12 docs/report.pdf         │
│ 2026-10-06 10:12:03                              [取消]  │
├──────────────────────────────────────────────────────────┤
│ 下载 · 腾讯云 COS               已完成                  │
│ 已保存到 /home/.../a.bin                                  │
└──────────────────────────────────────────────────────────┘
```

**分页与滚动**（与「凭据管理」同一套语义）：

- **分页**：`每页 [N] 条 ‹ x / y ›`——条数可选预设（5/10/20/50）也可**直接输入**
  （`allow-create`；非法值回落默认并提示）。**每页条数持久化**在
  `localStorage['vault.tasks.pageSize']`，**当前页不持久化**（页号是「我正看到哪儿」，
  重新打开从第 1 页开始才符合直觉）。条数变少时把越界页号夹回合法范围。
- **滚动**：列表区 **`max-height: 55vh` + `overflow-y: auto`**——任务多、输出又长时在列表内
  滚动（拖滚动条翻看本页其余条目），不会把下面「定时验证计划」那张卡片顶出屏幕。

**数据契约**：`api.listTasks()` → 数组，已按「进行中在前、其内按创建时间倒序」排好（照序渲染）。
每项 `{id, kind, title, status, cancel_requested, current, total, text, output, error,
created_at, finished_at}`，`status ∈ running | done | failed | canceled | interrupted`。

> **任务记录持久化到 `data/tasks.json`**（与日志同一个目录，不进数据库）：进程重启后仍在，
> 用户回来能翻到「上次那个下载到底成没成」。重启时**所有 `running` 一律改判 `interrupted`**
> ——线程随进程没了，继续显示「进行中」是骗人；但也没失败（用户没做错什么），故单列一档。
> 状态变迁立刻落盘，高频的 `progress()` 按 2 秒节流（进度条不需要毫秒级精度）；原子替换写入
> （先写 `.tmp` 再 `replace`），避免半个 JSON 让下次启动解析失败。已结束的只留最近 50 条。
> 不进库的理由：任务不参与查询与关联，进库白搭一次 schema 变动 + 迁移脚本，锁库时反而读不到。

- **进度条**：`total > 0` 给百分比；`running` 且 `total <= 0`（总量未知）用 `indeterminate`，
  免得显示成卡在 0%。只有 `running` 才显示进度条与「取消」。
- **状态标签**：进行中 / 已完成 / 失败 / 已取消 / **已中断**（`interrupted`）；`cancel_requested`
  为真时显示「正在取消…」。
- **取消**：`api.cancelTask(id)`，二次确认说明「会停止下载并清理未完成的临时文件」。
  点完**不本地改状态**——等 `vault:tasks` 推回来，否则会显示成「取消没生效」。
- **事件**：`vault:tasks` 的 detail 是**发生变化的那一条快照**（不是全量），就地更新/插入；
  拿不准时回退 `listTasks()`。组件卸载时移除监听。
- **侧栏角标**：维护一份「任务 id → 状态」表，靠快照前后对比算增减，避免每条事件都拉全量。

**「转到后台」**：带 `progress: true` 的操作在弹窗里跑时，多一个按钮 + 一行说明——点它只是
**关掉弹窗**，任务在后台继续（事件流与任务表都还在），用户可以去「任务」页看进度或取消。

### 定时验证计划（原「系统设置 → 定时验证计划」，已挪到本页）

第二张卡片，内容与对话框**原样搬来**（增删改查 + 立即运行），只换了位置。顶部刷新按钮一次刷
两样（后台任务 + 计划）——同页两个列表，只刷一个会让人以为另一个没更新。

> ⚠️ **数据库锁定期间，定时任务将不会实际执行验证**
>
> 卡片顶部一条常驻提示（`el-alert type="warning"`，不可关闭）。准确语义：保险库锁定时到点的
> 计划**照常入队**，但 `scheduler._run_schedule()` 在入口就**整轮跳过**——不逐条进验证、
> 不发起任何网络请求、凭据状态与 `last_valid_at` 一概不动，只留一条
> `定时计划 #N「…」跳过：数据库已锁定，本轮不执行验证` 的 **INFO** 日志。（早退比「逐条失败
> 后汇总成一行『异常 N』」可读：那行日志分不清是锁着还是真出错，还白占并发。）
> 计划的 `last_run_at` 照常推进——触发器确实响了，字段是「上次运行」而非「上次验证」；
> `next_run_at` 不受影响。解锁后自动恢复正常，不必重新启用计划。

## 系统托盘行为

应用支持最小化到系统托盘后台运行，MCP Server 和定时调度器持续工作。

### 窗口关闭行为

关闭窗口的行为由设置项 `close_action` 决定（"系统设置 → 窗口与关闭"可调整）：

| 取值 | 行为 |
|------|------|
| `ask`（默认） | 弹出确认框，让用户选择"直接退出"或"后台运行"，可勾选"记住我的选择" |
| `quit` | 直接退出程序（停止所有后台服务） |
| `background` | 隐藏窗口，最小化到托盘（MCP 与定时任务继续运行） |

| 操作 | 结果 |
|------|------|
| 托盘菜单"显示主窗口" | 恢复窗口显示 |
| 托盘菜单"锁定" | 清除内存密钥，下次显示窗口时需重新输入主密码 |
| 托盘菜单"退出" | 停止所有后台服务，真正退出进程 |

### 最小化到托盘

**不弹任何通知**（系统气泡与界面 toast 都没有）：缩到托盘是常规操作，窗口随即隐藏，
提示要么是噪音、要么根本看不到。托盘图标的状态色（见下）已足够表达「还在后台跑」。

**轻量模式开启时**（见「系统设置 → 窗口与关闭」），隐藏后还会进一步**释放界面文档**——后端把
网页换成一张静态占位页，前端 DOM 与 JS 堆全部释放；从托盘「显示主窗口」时后端重新加载前端。
释放期间后端不再向前端推事件（占位页上没有 `window.pywebview`）。**后台服务（MCP、定时任务）
与界面释放无关，照常运行**。细节见 [ARCHITECTURE.md §2.11](ARCHITECTURE.md)。

### 托盘图标状态

| 图标 | 含义 |
|------|------|
| 🟢 | MCP 运行中，有活跃 Token 连接 |
| 🔵 | MCP 运行中，无活跃连接 |
| 🔴 | MCP 已停止或出错 |
| ⚪ | 应用未解锁（主密码未输入） |

### 前端与托盘的交互

> Web 模式没有系统托盘：顶栏「最小化到托盘」按钮与设置里的「窗口与关闭 / 启动」卡片会被隐藏，
> web-bridge 对这些方法返回 no-op 或 `supported: false`。

前端通过 `window.pywebview.api` 控制托盘行为：

```javascript
// 最小化到托盘（前端调用，如用户点击"最小化"按钮）
await window.pywebview.api.minimize_to_tray()

// 锁定应用（清除内存密钥）
await window.pywebview.api.lock_vault()

// 查询托盘/MCP 状态
const status = await window.pywebview.api.get_tray_status()
// → { mcp_running: true, mcp_port: 8765, active_tokens: 1, is_locked: false }

// 关闭行为：读取 / 持久化设置（"系统设置 → 窗口与关闭"）
await window.pywebview.api.get_close_action()
await window.pywebview.api.set_close_action('background')

// 关闭确认弹窗中用户做出选择后回调（action: 'quit' | 'background'，remember=是否记住）
await window.pywebview.api.confirm_close_action('quit', true)

// 空闲自动锁定（"系统设置 → 安全"）
await window.pywebview.api.get_auto_lock()      // → { minutes: 5, options: [{value, label}, …] }
await window.pywebview.api.set_auto_lock(10)    // 0 = 关闭；非法档位返回 {ok:false, message}
await window.pywebview.api.touch_activity()     // 前端有用户操作时上报（内部约 30s 节流）

// 不锁定（"系统设置 → 安全"）：开启后空闲不锁、重启自动恢复；手动锁定仍清持久化密钥
await window.pywebview.api.get_never_lock()
// → { enabled, persisted, protection, protection_label }
await window.pywebview.api.set_never_lock(true)

// 轻量模式（"系统设置 → 窗口与关闭"）：开关只落库，行为发生在下次最小化到托盘时
await window.pywebview.api.get_light_mode()     // → { enabled: false }
await window.pywebview.api.set_light_mode(true) // → { ok: true, enabled: true }

// 开屏动画（"系统设置 → 外观"）：桌面用 claim（每进程一次）；
// Web 用 get_splash_disabled + sessionStorage 按标签页会话控制。
await window.pywebview.api.get_splash_disabled()    // → { disabled: false, always: false }
await window.pywebview.api.set_splash_disabled(true)
await window.pywebview.api.set_splash_always(true)  // 每次打开页面都重播；禁用时无效
await window.pywebview.api.claim_splash()           // → { show, reason, always }

// 开机自启动（"系统设置 → 窗口与关闭"）：直接增删操作系统自启条目，不落库
await window.pywebview.api.get_autostart()      // → { supported, enabled, platform, target }
await window.pywebview.api.set_autostart(true)  // → { ok, enabled }；失败时 { ok:false, message }
```

> **开屏动画**：桌面端挂载时调用 `claim_splash()`（按进程只认领一次，轻量模式重载页面不重播）；
> Web 端用 `sessionStorage` 按标签页会话只播一次（刷新不重播，新标签页视为新启动）。
> 开启「总是展示开屏动画」后上述限制放宽：桌面端后端会把 `claim_splash()` 的 `show` 始终置为
> true，并在托盘唤出时推送 `vault:window_restored` 事件由前端重播；Web 端忽略 sessionStorage
> 标记，每次刷新都播。两端都要求未被禁用且窗口 **≥ 1024×600**，结束后从 DOM 移除。组件是自包含
> Web Component（`src/splash/keyrealm-splash.js`）；保险库锁定/未创建时，**密码表单直接嵌在开屏右侧**
> （`components/SplashAuth.vue`），解锁成功才播放转场；已解锁时显示「点击任意处进入」。
> 「禁用开屏动画」优先于「总是展示」，开启时仍走独立 Unlock / Setup 页面（`components/AuthBackdrop.vue`
> 提供静态星野背景）。`prefers-reduced-motion` 下退化为静态画面。

> **锁定一律只看 `vault:locked` 事件**：`lock_vault()` 是唯一加锁出口，界面按钮 / 托盘菜单 /
> 空闲自动锁都汇入它并由它广播。前端收到事件后调 `appStore.applyLocked()` 清空明文，
> `watch(appStore.unlocked)` 负责跳回 `/unlock`。

## Pinia Store 设计

### `useVaultStore`（核心状态）

> **解锁态不在本 store**：`unlocked` / `unlock()` / `setupMasterPassword()` 都在 `useAppStore`
> （见下），本 store 只管凭据、分组、插件与批量验证。

```javascript
{
  // 状态
  credentials: [],
  groups: [],
  plugins: [],
  loadingCredentials: false,
  filters: { group_id: null, credential_type: null, credential_types: null, status: null, search: '' },
  batch: { running, done, total, currentName, status, ids, trigger, result },

  // 计算属性
  enabledPlugins, pluginByType,        // 已启用插件 / 按 credential_type 索引
  typeOptions, typeGroups,             // 「新建凭据」的类型下拉（按类别分组）
  pluginTree,                          // 左侧目录树：类别节点 → 服务节点
  groupOptions,                        // 分组下拉

  // 操作
  fetchCredentials(), createCredential(payload), updateCredential(id, payload),
  deleteCredential(id), deleteCredentials(ids), verifyCredential(id),
  batchVerify(scope, groupId, credentialType, credentialIds, concurrency, timeout),
  fetchBatchOptions(),                 // 批量验证的并发/超时可选值（对话框回填）
  fetchGroups(), createGroup(payload), updateGroup(id, payload), deleteGroup(id),
  fetchPlugins(),                      // 插件放入 plugins/ 目录即自动加载，无安装入口
  setPluginEnabled(type, enabled),
  clear(),                             // 锁定时清空内存明文
  // 后端事件 / 快照接回
  upsertCredential(cred), applyCredentialUpdated(cred),
  applyBatchStarted(detail), applyBatchProgress(detail), applyBatchDone(detail),
  resumeBatchFromTasks(),
}
```

> 「创建前重复检测」是 `api.checkDuplicateCredential(type, data)`，由 `CredentialForm.vue`
> **直接调用**（不进 store）。

### `useMcpStore`（MCP 设置）

```javascript
{
  // 服务运行状态
  status: { running: false, host: '127.0.0.1', port: 8765, active_tokens: 0, url: '' },
  permissions: [],           // [{ tool_name, description, enabled }]
  token: null,               // { exists, token_prefix }
  busy: false,               // 启动/停止进行中

  // 计算属性
  running, serverUrl, clientConfig,   // clientConfig() → 可直接粘进客户端的 JSON

  // 操作
  fetchStatus(), start(), stop(),
  fetchPermissions(), setPermission(toolName, enabled),
  fetchToken(), rotateToken(),        // 作废旧 Token 并签发新的（明文仅返回一次）
  refreshAll(),
  clear(), applyStatusEvent(detail),
}
```

### `useAppStore`（引导 / 解锁态 / 托盘状态）

```javascript
{
  // 状态
  bootstrapped: false,       // 是否已问过后端「有没有初始化过」
  initialized: false,        // 是否已设过主密码
  unlocked: false,           // 当前是否已解锁
  tray: { mcp_running: false, mcp_port: 8765, active_tokens: 0, is_locked: true },

  // 操作
  bootstrap(force),          // 读初始化/解锁状态（并发去重 + 结果缓存）
  setupMasterPassword(pw), unlock(pw),
  applyLocked(),             // 锁定后的**前端收尾**：清空明文 + 托盘置灰（不调后端）
  lock(),                    // 调 api.lockVault()，finally 里走 applyLocked()
  reportActivity(),          // 节流上报用户活动（约 30s 一次），供后端空闲锁定计时
  refreshTray(), minimizeToTray(),
}
```

> **`applyLocked()` 为什么单独拆出来**：后端加锁有三个入口（界面按钮 / 托盘菜单 / 空闲自动锁），
> 但它们最终都汇入 `api.lock_vault()` 并广播 `vault:locked`。界面点按钮走 `lock()`（调后端）；
> 另外两个入口**后端已经锁好了**，前端只需 `onEvent(EVENTS.vaultLocked)` → `applyLocked()` 做收尾，
> 不能再调一次 `lockVault()`。

### `useProxyStore`（代理注册表）

```javascript
{
  items: [], globalId: null, globalUrl: '',
  testing: false, testingId: null, result: null,
  fetch(), create(name, url), update(id, name, url), remove(id), setGlobal(id),
  runTest(id = null),        // id = null 表示测「当前全局生效的那个」
  clearResult(),
}
```

> 测试的进行态与结果放在 store 而不是页面局部 ref：`<router-view>` 没有 keep-alive，
> 切页会卸载组件，后端跑完却写进已销毁的实例 → 用户看到「测试被中断」。

## 前端事件监听

后端通过 `window.evaluate_js()` 推送以下事件：

| 事件名 | 触发时机 | detail |
|--------|----------|--------|
| `vault:credential_updated` | 凭据状态变化 | `{id, status, status_detail}` |
| `vault:credentials_changed` | 凭据增删 | `{}` |
| `vault:batch_verify_started` | 批量验证开始 | `{total, skipped, trigger, credentials:[凭据id…]}`——`trigger` ∈ `manual`/`mcp`/`schedule`，前端据此决定是否整页互斥；`credentials` 用于把对应行的「验证」按钮置成 loading |
| `vault:batch_verify_progress` | 批量验证进度 | `{current, total, credential_name, status}` |
| `vault:batch_verify_done` | 批量验证完成 | `{total, valid, invalid, error, skipped}`（skipped = 因 `batch_verify=false` 被跳过的条数）；被取消时额外带 `canceled: true` 与 `done: <已处理条数>` |
| `vault:mcp_status` | MCP 服务状态变化 | `{status, port}` |
| `vault:close_confirm` | 用户点击关闭且关闭行为为"询问" | `{}`（前端弹出退出/后台选择框） |
| `vault:window_restored` | 桌面端从托盘唤出窗口 | `{}`（前端读取「总是展示开屏动画」决定是否重播；轻量模式重载页面时不推送） |
| `vault:locked` | 保险库被锁定（界面按钮 / 托盘菜单 / 空闲自动锁**任一入口**） | `{}`（前端清空明文并跳回解锁页） |
| `vault:tasks` | 某个后台任务状态变化 | 该条任务的快照（不是全量列表），前端就地更新/插入对应行 |
| `vault:plugins_changed` | 插件目录扫描结果变化 | 由 `plugin_manager` 推送（前端重拉插件列表） |
| `vault:action_stream` | 流式操作（如长输出动作）的增量输出 | 由 `stream_credential_action` 推送 |

> **加锁事件只有一条 `vault:locked`**：三个加锁入口全部经 `api.lock_vault()`，由它统一广播，
> 所以前端只需监听一个事件即可在任何入口下保持界面一致。
